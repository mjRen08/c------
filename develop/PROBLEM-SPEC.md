# CodeMaster OJ 题库编写规范（v1）

你要为一个中文 C 语言学习网站的「OJ 练习场」编写题库数据。

## 输出要求（极重要）

- 只输出一个文件：在你的任务里给出的 `OUTFILE` 绝对路径。
- 文件内容就是一条 `export default [ ... ];` 的 JavaScript 数组字面量（**不是** JSON，允许尾随逗号，字符串用双引号或单引号都行，但**字符串内部必须用 `\n` 表示换行，不能出现真实换行**）。
- 文件编码 UTF-8（无 BOM）。文件里**不要**写 import/export 以外的东西，不要写注释以外的 JS 代码。
- 不要新增其它文件，不要修改项目里的任何其它文件。

## 数据结构

```js
export default [
  {
    id: 1,                     // 全局唯一正整数（本批次从 START_ID 开始连续编号），按题目顺序递增
    courseId: 'basics',        // 必须与课程节次里的 courseId 完全一致
    chapter: 1,                // 1..5
    lesson: '核心概念与基本模型',
    level: 'easy',             // easy | medium | hard（第一题 easy、第二题 medium、第三题 hard，务必依次由浅入深）
    label: '入门',             // easy→'入门'、medium→'进阶'、hard→'挑战'
    title: '……',              // 8 个汉字以内的短标题，不带题号
    description: '……',        // 1~3 句中文题干，写清「输入什么、要做什么、输出什么」
    input: '……',              // 中文描述输入格式
    output: '……',             // 中文描述输出格式
    publicCases: [ { input: '……', output: '……' } ],   // 2 条
    hiddenCases: [ { input: '……', output: '……' } ],   // 2 条
    starter: '#include <stdio.h>\n\nint main(void) {\n    …\n    return 0;\n}',
    solution: '#include <stdio.h>\n…完整可编译通过全部 4 个测试点的 C11 代码',
    checks: [ ['正则表达式', '中文提示：必须……'] ]
  }
]
```

## 硬性规则（请逐条自查）

1. **input/output 都是完整的一等字符串**
   - `input` 就是程序 stdin 的**全部内容**，可以包含 `\n`。
   - `output` 必须**以 `\n` 结尾**（因为程序用 `printf` 输出换行）。若题目是「无输入」，`input` 写 `'无'`。
   - 期望输出末尾不要有空格行、不要有额外空行。
2. **solution 必须是真的对的**：它要能用 `clang -std=c11` 编译通过，并对 4 个测试点（2 公开 + 2 隐藏）全部输出正确答案。
   - 只用标准库（`stdio.h` `string.h` `math.h` `stdlib.h` `ctype.h` `limits.h` `float.h`）。
   - `main` 必须 `return 0;`；`scanf` 读不到数据时不要输出垃圾内容。
   - 不要用 `gets`、不要用 `scanf_s`、不要用可变长数组以外的 C99 之外特性要谨慎（`-std=c11` 即可）。
   - 浮点输出统一用 `%.2f`（题目里说明保留两位小数），避免精度争议。
3. **starter 必须能编译通过**（可以运行结果不对），它是给学生的骨架：保留 `#include`、`int main(void)`、`scanf` 读取、`return 0;`，把核心逻辑留成一行中文注释。
4. **checks 至少 1 条**，用 `[正则, 提示]` 形式，正则会被 `RegExp#test` 用在**去掉注释后的源码**上。
   - 只检查那些「不满足就一定做错」的点，宁少勿多，不要写会误伤正确解的正则。
   - 例如：`['/printf\\s*\\(/', '必须使用 printf 输出结果。']` 或 `['/scanf\\s*\\(/', '必须读取输入。']`。
5. **测试点要有区分度**：2 条公开是常规样例（能看懂题意），2 条隐藏覆盖边界（0、负数、单元素、最大值、空行、恰好相等……）。
6. **同一课程内 15 个题目不得重复**：题干、算法、输出格式都要有区别；同一节次的 3 题是「同一知识点，由浅入深」。
7. 题目难度与课程定位一致：入门课程不要出指针/动态内存；高级课程不要出只有 3 行代码的题。
8. 所有文本用简体中文，术语与教材一致（如「标准输入」「数组长度」）。
9. **不要**在字符串里出现未转义的英文双引号——C 代码里用 `\"` 或直接用单引号；JS 字符串建议统一用单引号包裹，内部 C 代码里的 `'` 需写成 `\'`（更推荐：JS 用双引号包裹含单引号的 C 代码，C 代码里含双引号时写成 `\"`）。请务必逐个检查转义，写完后自己肉眼过一遍 `solution` 和 `starter` 的转义是否正确。

## 与 UI 有关的约定

- 每节课 3 题固定：第 1 题 easy（入门）、第 2 题 medium（进阶）、第 3 题 hard（挑战）。
- `id` 在本批次内从 `START_ID` 开始，按数组顺序连续 +1。
- 顺序必须严格按上面的课程节次表排列：先 course 内 chapter 1..5，每 chapter 内 3 题。
